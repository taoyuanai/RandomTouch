# 拾笺 · 抽卡小程序设计说明

> 说明（2026-11-10）：本文档对应上一版「拾笺」。当前 `/` 已按用户要求切换为「今日做点小事」V2.2 单文件原型（`static/day_small_things_v2.html`），并做了「页面顶部固定、下方独立滚动」的布局调整；原始文件见 `resources/deepseek_html_20261110_daba72.html`。以下内容仅作遗留参考。

## 1. 设计定位

参考原型《拆信》的**页面架构、交互仪式与白墨极简视觉**，把「拆信 / 集词」转译为「抽词笺 / 集句」：

- 一本书拆成词，每天拆一封信 → 一组四时词笺，每次抽一枚词。
- 抽卡不是纯数值掉落，而是「从字词里抽出一句人间」：每枚词笺都带出处、原句与笺注。
- 所有抽卡结果由服务端计算并持久化，前端只负责拆包、翻面与展示。

运行形态：移动端优先的 Web 小程序原型（手机壳 390px），可直接在浏览器演示，也便于后续移植到微信小程序。

### 抽卡页

- 品牌行：`拾 笺` + 本期笺主。
- 卡池主视觉：期数、主张、三枚 SSR 特色词笺、概率公示。
- 抽卡面板：保底进度、免费抽、单抽、十连、笺 / 墨 / 收集数。
- 最近拾到：最近两批抽卡结果。
- 当日签句。

### 我的词笺

- 统计：已拾词笺 / 累计抽卡 / SSR 数。
- 稀有度筛选：全部 / SSR / SR / R / N。
- 双列词笺网格；重复卡显示 `×N`。
- 轻触词笺 → 分享卡。

### 四时图鉴

- 春、夏、秋、冬四组，每组 5 枚。
- 已获得：词、稀有度、出处；未获得：暗格 `？`。
- 每季完成度进度条。

### 我的

- 笺（抽卡券）、墨（重复卡转化）、已收数。
- 每日签到领 10 笺；100 墨换 10 笺。
- 抽卡记录（最近 8 次）、重置本期数据。

## 4. 核心流程

### 4.1 抽卡状态机

```
idle → loading → pack(卡包待拆) → opening(拆包动画) → revealed(出卡/翻牌) → idle
```

- `idle`：首页三个入口可点击。
- `loading`：请求服务端，按钮防重入。
- `pack`：展示卡包与「轻触拆开」。
- `opening`：封口翻起、火漆消失（620ms）。
- `revealed`：单抽展示大卡（可翻面）；十连展示 2 列卡阵（可逐张翻面）。
- 关闭或「收下」回到 `idle`；「再抽一次」重新进入 `loading`。

### 4.2 首次使用（空状态）

1. 进入抽卡页，免费抽可用。
2. 点击「今日免费一抽」→ 拆包 → 翻面 → 收下。
3. 词笺进入「我的词笺」，图鉴对应暗格点亮。
4. 用 10 笺十连，体验保底与重复转墨。

## 5. 抽卡规则

| 项目 | 规则 |
|---|---|
| 概率 | SSR 3% / SR 12% / R 30% / N 55% |
| 单抽 | 1 笺 |
| 十连 | 10 笺 |
| 每日免费 | 每日首次单抽免费（自动使用） |
| 每日签到 | 每日领 10 笺 |
| SSR 保底 | 累计 80 抽必得 SSR |
| SR 保底 | 累计 10 抽必得 SR 及以上 |
| 十连保底 | 十连必得 SR 及以上（第 10 抽兜底） |
| 重复处理 | N +1 墨、R +2 墨、SR +10 墨、SSR +50 墨 |
| 墨的用途 | 100 墨换 10 笺 |
| 初始资源 | 50 笺 |
| 保底计数 | 出 SSR 重置双计数；出 SR 重置 SR 计数 |

服务端逐抽判定：

1. SSR 计数 +1；若达到 80，直接 SSR。
2. 否则 SR 计数 +1；若达到 10，或触发十连兜底，直接 SR。
3. 否则按概率表抽取。
4. 出 SSR 重置 SSR/SR 计数；出 SR 重置 SR 计数。

## 6. 数据模型

### 词笺 Card

```json
{
  "id": "gong-chan-juan",
  "word": "共婵娟",
  "rarity": "SSR",
  "series": "autumn",
  "source": "苏轼《水调歌头》",
  "quote": "但愿人长久，千里共婵娟。",
  "note": "把不能见面的，交给同一轮月亮。"
}
```

一套 20 枚，春 / 夏 / 秋 / 冬 各 5 枚；SSR 3 枚、SR 6 枚、R 5 枚、N 6 枚。

### 玩家状态 PlayerState

落盘位置：`history/players/<session player_id>.json`（已被 `.gitignore` 忽略）。

```json
{
  "player_id": "32 位 hex",
  "created_at": "2026-11-06 09:30:00",
  "tickets": 50,
  "ink": 0,
  "collection": {
    "yue": { "count": 2, "first_draw_at": "2026-11-06 09:31:02" }
  },
  "pity": { "ssr": 12, "sr": 3 },
  "last_free_date": "2026-11-06",
  "last_gift_date": "2026-11-06",
  "draw_count": 11,
  "history": [
    {
      "at": "2026-11-06 09:31:02",
      "count": 10,
      "free": false,
      "results": [{ "id": "yue", "rarity": "N", "is_new": false }]
    }
  ]
}
```

- 写入使用进程内 `RLock` + 临时文件 `os.replace` 原子落盘。
- 历史最多保留 30 批，接口默认返回全部 30 批。
- 玩家身份由 Flask signed session 中的 `player_id` 决定；换浏览器 = 新玩家。

## 7. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/gacha/state` | 卡池、词笺目录、收集、保底、统计、历史 |
| POST | `/api/gacha/draw` | `{"count": 1}` 或 `{"count": 10}`，单抽自动使用当日免费 |
| POST | `/api/gacha/daily-gift` | 每日签到 +10 笺 |
| POST | `/api/gacha/exchange` | 100 墨 → 10 笺 |
| POST | `/api/gacha/reset` | 重置本期数据（演示用） |

`/api/gacha/draw` 响应：

```json
{
  "results": [
    { "card": { "...card..." }, "is_new": true, "ink": 0 }
  ],
  "used_free": true,
  "cost": 0,
  "payload": { "...与 /state 相同..." }
}
```

错误统一返回 `{ "error": "code", "message": "中文说明" }`，HTTP 400。

## 8. 视觉规范

- 底色：页面 `#F5F5F7`、嵌套 `#EFEFF2`、卡面 `#FFFFFF`。
- 文字三级：墨 `#111111` / 灰 `#737373` / 淡灰 `#B8B8BC`。
- 强调色：印章红 `#A83F39`，全站唯一彩色；SSR 才使用红色。
- 稀有度：SSR 红描边、SR 墨描边、R 灰描边、N 淡灰描边。
- 字体：标题与词笺用宋体（Songti SC / Noto Serif SC），正文用系统无衬线。
- 组件语言：无描边白色面板 + 轻投影；胶囊按钮；`999px` 圆角；火漆红章。
- 动效：页面 250ms 上浮淡入；拆包封口 550ms 翻转；卡片 650ms 3D 翻面；十连结果 55ms 错峰弹入。
- 分享卡：纯白底 + 红印章标签，保证外发截图始终「白纸黑字红印」。

## 10. 后续扩展

### 移植微信小程序

- 页面：`pages/draw`、`pages/cards`、`pages/codex`、`pages/me`；抽卡与海报为自定义组件。
- 身份：`wx.login` → 服务端换 `openid`，替代当前 session。
- 数据：`history/players/*.json` 替换为云数据库 / MySQL。
- 抽卡判定必须保留在服务端；客户端只传 `count`。
- 分享海报：服务端渲染卡片 → COS → `wx.saveImageToPhotosAlbum`。

### 玩法与运营

- 卡池版本化：每期一套词笺，支持复刻与限定。
- 概率 UP：指定 SSR 占 SSR 出率的 50%。
- 集齐奖励：集齐一季解锁专属签句 / 背景。
- 每日任务：抽 1 次、分享 1 次、图鉴浏览，奖励笺。
- 保底可视化：首页展示「距 SSR 还差 N 抽」。
- 抽卡记录与概率公示：满足合规与用户信任。

### 工程与安全

- 抽卡接口限流与幂等键，防止连点与重放。
- 服务端记录每次随机结果与种子审计，概率可复核。
- 状态文件迁移到数据库后，加唯一索引与事务。
